## 七、🚨 故障处理

**A. 某个节点连不上?** 先在 Hiddify 里**换另一个节点**(JP/SG/Hy2/Reality 共 4 个),能用就先用着。再排查:
1. 换个本地网络试(切手机热点),排除自己网络问题。
2. 测端口(IP 换成对应服务器的静态 IP):
   - Windows:`Test-NetConnection 16.76.73.144 -Port 443`
   - Mac:`nc -vz -w 5 16.76.73.144 443`
   - 通 → 服务器没事,是客户端问题(节点选中?Hiddify 开着?)。
   - 不通 → 进 B。
3. SSH 上那台服务器:`sudo systemctl restart sing-box`,再测。

**B. IP 被墙了(22 和 443 都不通)?**
该服务器的静态 IP 被封了。重新抽一个:
1. Lightsail → 对应区域 Networking → 删掉旧静态 IP → Create 新的 → 绑到实例。
2. 测新 IP 的 22 端口,通才用。
3. 同步服务器记录:`sudo sed -i 's/^SERVER_IP=.*/SERVER_IP=新IP/' /etc/sing-box/meta.env`
4. 在各客户端把对应节点的链接 IP 改成新 IP(或重新生成链接导入)。

**C. 抽几次 IP 都被墙?**
AWS 新加坡 IP 段对国内不友好。考虑:
- 换 **AWS 东京区域**(重建实例,线路通常更好)。
- 或换 **CN2 GIA 线路**的服务商(花钱但稳)。

## 八、🔑 安全

- 节点钥匙(UUID / vless 链接)等于密码,**别公开发、别截图传**。
- 给朋友用 → 用 `add-user.sh` **每人开独立 UUID**,不要共用。
- Gist 务必设 **Secret(私密)**。
- 定期(或怀疑泄露时)用 `add-user.sh` 换新 UUID、删旧的。
